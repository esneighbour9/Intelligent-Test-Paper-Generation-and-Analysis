# 项目整体规划

**课题：** 基于 Spring Boot 的智能组卷与试卷分析系统设计与实现
**技术栈：** Spring Boot + Vue 3 前后端分离，MySQL + Redis
**核心亮点：** 基于改进遗传算法的智能组卷 + 基于经典测量理论（CTT）的试卷质量分析与知识点诊断
**规划周期：** 2026.10 — 2027.05（约 8 个月）

---

## 一、项目目标与成果清单

### 1.1 总目标
建成一个可稳定运行的智能组卷与试卷分析系统，形成「题库—组卷—考试—评阅—分析—反馈」的完整闭环；所实现的改进遗传算法在满足全部组卷约束的前提下，组卷成功率与试卷质量指标优于随机组卷与标准遗传算法。

## 五、智能组卷算法方案（核心亮点）

### 5.1 问题建模
将组卷抽象为**多约束、多目标组合优化问题**。设题库按题型分组，决策变量为每道题是否入选。

**约束条件：**
- 试卷总分等于目标总分
- 各题型题量与分值符合模板
- 知识点覆盖率不低于阈值
- 难度分布符合目标（如易:中:难 = 3:5:2）
- 题目不重复、答题时间接近目标时长

**优化目标（适应度函数）：** `f = w1·g难度 + w2·g知识点 + w3·g结构 + w4·g时间 − 惩罚项`
- g难度：试卷实际难度分布与目标分布的距离（越小越好）
- g知识点：知识点覆盖率与均衡度
- g结构：题型与分值结构符合度
- g时间：总答题时间贴近度
- 惩罚项：对违反硬约束（总分、题量、重复）的方案施加惩罚

### 5.2 改进遗传算法设计
- **编码：** 按题型分段编码，每段为一组题目 ID，天然保证题型题量约束；
- **初始化：** 依据约束随机生成可行初始种群；
- **选择：** 锦标赛选择 + 精英保留（防止最优解退化）；
- **交叉：** 按题型分段交叉（同段内交换题目）；
- **变异：** 随机替换题目，采用**自适应交叉/变异概率**（随进化代数与个体优劣动态调整，兼顾收敛速度与种群多样性）；
- **终止：** 达到最大进化代数或适应度阈值。

### 5.3 对比实验（论文核心数据）
在相同题库与约束下，对比三种方法各重复运行 N 次（如 50 次），统计：组卷成功率、平均适应度、收敛代数、难度贴近度、知识点覆盖率。用表格与折线图呈现改进算法的优势。

## 六、试卷分析方案

基于经典测量理论（CTT）：

| 指标 | 对象 | 计算方法（要点） |
|---|---|---|
| 难度 P | 试题 | 得分率 / 通过率 |
| 区分度 D | 试题 | 高低分组得分率之差（或与总分的相关） |
| 信度 | 试卷 | Cronbach's α 或 KR-20 |
| 效度 | 试卷 | 内容效度（与知识点/大纲符合度） |
| 分数分布 | 试卷 | 直方图、平均分、标准差、及格率 |

在统计基础上增加**知识点掌握诊断**：按知识点聚合得分率，输出学生/班级的知识点雷达图与薄弱知识点清单。全部结果用 ECharts 可视化。

## 九、风险管理

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 算法收敛慢 / 早熟 | 组卷质量不达标 | 自适应概率 + 精英保留；控制种群规模与代数；必要时引入混合策略 |
| 权重参数难调 | 试卷质量不稳定 | 设计参数实验，记录不同权重下的指标，选取稳健配置 |
| 题库数据不足 | 无法验证 | 提前构造/收集足量题目，标注难度与知识点 |
| 前后端联调延期 | 挤压测试时间 | 先定接口契约（Swagger），前后端并行开发 |
| 论文与实现脱节 | 答辩被质疑 | 设计文档先行，实现严格对照设计，论文直接复用设计与实验数据 |
| 时间冲突（其他课程） | 进度延误 | 按里程碑滚动检查，阶段 5 预留缓冲 |

## 十、答辩准备要点

1. **讲清楚“智能”在哪：** 组卷不是随机抽题，而是把约束建模为整数规划问题并用改进遗传算法求解——这是全篇的创新点。
2. **用数据说话：** 展示改进 GA 与随机/标准 GA 的对比图表（成功率、收敛曲线、难度贴近度）。
3. **形成闭环：** 强调系统从组卷到知识点诊断的一体化，区别于只做组卷或只做分析的现有系统。
4. **能答追问：** 提前准备“适应度权重怎么定”“为什么用遗传算法不用别的”“难度怎么标定”“信度怎么算”这几个高频问题。
5. **现场演示：** 准备一段流畅的组卷 + 分析演示，最好有可复现的样例数据。
