## 一、使用说明与前提假设

1. **本计划从 2026-11-05（阶段 2 进行中）起排**，覆盖阶段 2–8，止于 2027-05 答辩。
2. **每周有效投入按 12–15 小时估算**（课余时间）。若某周实际投入不足，按"整周顺延"处理，并消耗预留缓冲（W9、W15）。
3. **校历假设**（编制时无法核实，请在开学后对照校历修正）：
   - 2027 年 1 月上旬为期考试周，1 月中下旬至 2 月下旬为寒假；
   - **2027 年春节为 2 月 6 日**，前后约 1–2 周效率明显下降（W15 已按此布置）；
   - 若学校有中期检查（一般 3 月前后），已在 W20 预留准备窗口。
4. **协作方式**：Claude 负责写代码与文档并逐段讲解，用户负责运行、理解、验收。每周验收不只是"跑通了"，还包括**用户能用自己的话讲清本周做了什么、为什么这么做**——这是为答辩做的积累。
5. **每周固定动作（硬性）**：周日晚用 30 分钟验收本周完成定义（DoD）→ 提交代码 → 更新文末进度跟踪表 → 定下周目标。

## 三、阶段 2：需求与设计（2026-11-02 ~ 11-29，W1–W4）

> 本阶段结束时，应达到"照着文档就能编码"的程度，且任何设计问题在纸上改的成本远低于在代码里改。

**阶段目标**：需求、数据库、接口、算法四份设计文档齐备，且能直接指导编码。
**不做的事**：不写业务代码（W4 只搭骨架做环境验证）。
**延期预案**：若超期，优先保数据库设计与接口文档；用例图可先简化，答辩前补全。

### W1（11-02 ~ 11-08）需求细化

- **任务**：按 3 类角色 × 6 模块梳理功能清单；绘制用例图（PlantUML 或 draw.io）；明确题库数据规格（题型、难度等级、知识点层级、题目状态流转）；列出非功能需求（性能、安全、兼容性）。
- **产出**：`docs/03-需求/01-需求规格说明书.md`
- **验收**：每条需求可追溯到用例；6 模块无遗漏；与开题报告"拟解决的关键问题"一一对应。

### W2（11-09 ~ 11-15）总体设计与数据库设计

- **任务**：绘制系统架构图与模块图；完成 E-R 设计；编写约 20 张表的建表脚本（含索引与字典）；本地 MySQL 8.0 实际执行通过。
- **产出**：`docs/04-设计/01-数据库设计.md`、`sql/01_schema.sql`
- **验收**：一条命令完成建库；每个用例都能找到支撑它的表；关键查询字段有索引说明。

### W3（11-16 ~ 11-22）接口设计与算法设计

- **任务**：按模块列出 RESTful 接口清单（统一返回体、错误码、分页约定、JWT 约定）；编写 GA 算法设计文档（编码方式、适应度函数构成、算子设计、改进点、对比实验方案与达标线）。
- **产出**：`docs/05-接口/01-接口设计.md`、`docs/04-设计/02-算法设计.md`
- **验收**：前端仅凭接口文档即可 mock 开发；算法设计文档足够具体，W5 可直接照它编码。

### W4（11-23 ~ 11-29）设计定稿 + 技术预热

- **任务**：设计评审（对照开题报告逐项检查一致性）；搭建 Spring Boot 骨架工程（能启动、跑通一个 `/api/ping`）；验证环境全链路（JDK、Maven、MySQL、Redis、Node）；确定模拟题库的生成方案。
- **产出**：可运行的骨架工程；`docs/00-规范/开发环境搭建.md` 补充实际版本号
- **验收**：本机 `mvn spring-boot:run` 成功、Postman 调通 demo 接口。
- **里程碑**：合并 `dev → main`，打 Tag `v0.2-设计定稿`。

## 四、阶段 3：算法设计与实现（2026-11-30 ~ 2027-01-03，W5–W9）

> 算法是论文核心与答辩最容易追问的部分，**先于业务系统独立完成**。
> 工程上做成独立 Maven 模块（`backend/paper-engine`，纯 Java + JUnit，不依赖 Spring），好处有三：不受 Web 环境干扰、可独立跑实验、后期后端直接调用。

**阶段目标**：改进 GA 达到预设达标线，并产出可直接写进论文的三方对比实验数据。
**延期预案**：优先保"标准 GA + 自适应改进 + 对比实验"主线；参数实验网格可缩到 2×2，权重调优以记录过程代替穷举。

### W5（11-30 ~ 12-06）数据准备与适应度函数

- **任务**：实现模拟题库生成器（可配置题型、知识点分布、难度分布，生成 500 题左右并固定随机种子）；定义 `Question` 模型；实现按题型分段编码；实现适应度函数与硬约束检查（总分、题量、不重复）。
- **产出**：`paper-engine` 模块代码 + 单元测试
- **验收**：同一随机种子生成相同题库；对构造的好坏试卷，适应度打分方向正确；约束检查能逐条报出违规项。

### W6（12-07 ~ 12-13）标准遗传算法跑通

- **任务**：实现初始化、锦标赛选择、分段交叉、变异、精英保留；端到端跑通"约束 → 组卷 → 输出试卷"；统计约束违规率。
- **产出**：标准 GA 可运行版本
- **验收**：标准 GA 在模拟题库上组卷成功率 ≥ 90%（可行解比例），单次组卷耗时 < 3 秒。

### W7（12-14 ~ 12-20）自适应改进与参数实验

- **任务**：实现自适应交叉/变异概率（随代数与个体适应度动态调整）；做参数实验：种群规模（50/100/200）× 代数（100/200/500）× 权重组合，记录成功率与收敛代数。
- **产出**：参数实验记录（CSV）
- **验收**：确定一组稳健的默认参数并写入算法设计文档；改进 GA 相比标准 GA 在成功率或收敛速度上有可量化优势。

### W8（12-21 ~ 12-27）对比实验（论文核心数据）

- **任务**：随机组卷 / 标准 GA / 改进 GA 各重复 50 次，统计组卷成功率、平均适应度、收敛代数、难度贴近度、知识点覆盖率；生成论文用表格与折线图。
- **产出**：实验数据表 + 图表（存入 `docs/06-测试/` 或 `docs/07-论文/images/`）
- **验收**：达到预设达标线（建议：成功率 ≥ 95%，适应度较标准 GA 提升 ≥ 10%，知识点覆盖率 ≥ 90%）；未达标则记录原因与调参过程，**不无限调参**。

### W9（12-28 ~ 01-03）收尾与缓冲

- **任务**：算法设计文档回填最终参数与实验结论；封装对外门面接口（供后端调用）；若 W8 有遗留问题，本周解决；**顺带完成后端工程骨架与依赖清单**（缓解 1 月考试周挤压）。
- **里程碑**：合并 `dev → main`，打 Tag `v0.3-算法完成`。

## 五、阶段 4：后端核心功能（2027-01-04 ~ 01-31，W10–W13）

> 1 月上旬有考试周，本阶段实际只有约 3 周有效时间。W9 已提前搭好骨架，本阶段专注业务。

**阶段目标**：后端六模块接口全部可用，核心链路（组卷 → 发布 → 作答 → 评阅）走通。
**延期预案**：考试管理可先实现"发布 + 客观题自动阅卷"，主观题改为人工录分，后续版本补齐。

### W10（01-04 ~ 01-10）工程化基建

- **任务**：分层结构（Controller/Service/Mapper）、统一返回体与全局异常、MyBatis-Plus 配置、JWT + Spring Security 认证、Knife4j 接口文档；建表脚本落库。
- **验收**：登录 → 拿到 Token → 访问受保护接口，全链路通。

### W11（01-11 ~ 01-17）系统管理 + 知识点 + 题库

- **任务**：用户/角色/权限管理；知识点树 CRUD；题目 CRUD、分页检索、Excel 批量导入模板与解析、题目审核状态流转。
- **验收**：用 Excel 批量导入 300 题成功；题目可按知识点/难度/题型筛选。

### W12（01-18 ~ 01-24）智能组卷模块

- **任务**：手工组卷、模板组卷、智能组卷（接入 W9 的算法引擎）三个入口；组卷参数配置；试卷预览与微调（换题）。

### W13（01-25 ~ 01-31）考试管理模块

- **任务**：考试发布、在线作答、客观题自动评阅、主观题人工阅卷、成绩管理。
- **验收**：用 Knife4j/Postman 完成"组卷 → 发布 → 作答 → 评阅 → 出成绩"整条链路。
- **里程碑**：合并 `dev → main`，打 Tag `v0.4-后端完成`。

## 十一、关键依赖与并行原则

1. **设计是编码的前置**：W3 接口文档未定稿，前端不进入页面开发（可先做布局）；W3 算法设计未定稿，W5 不进入编码。
2. **算法与业务并行**：W5–W9 算法开发期间，W9 并行搭后端骨架，为 W10 抢出考试周的时间。
3. **前端可 mock 先行**：接口文档定稿后，前端可基于 mock 数据开发，联调阶段只替换请求层——这是压缩 2 月风险的核心手段。
4. **数据先行**：分析模块依赖真实作答数据，W17 必须准备好种子数据，否则 W18–W19 会空转。
5. **文档随阶段走**：每阶段产出的文档既是交付物，也是论文素材；不要拖到 4 月再回头补。
